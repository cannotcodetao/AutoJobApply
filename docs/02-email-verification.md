# 二、邮箱来源分级与核实方法

> 核心问题：**这个邮箱地址，你有多大把握？**
> 「有把握」不是一个感觉，是可以分级的事实。

---

## 一、来源四级分级

| 级别 | 来源 | 可信度 | 能不能直接投 |
|---|---|---|---|
| **A** | 企业官网招聘页 / 官方招聘平台的「简历投递邮箱」 | 最高（但仍需 MX 体检） | ✅ 可以 |
| **B** | 高校就业网发布的**原始简章**（企业提供给学校的版本） | 高 | ✅ 可以，需注明出处 |
| **C** | 官方就业服务平台（如 24365、省级大学生就业平台）公告 | 中高 | ⚠️ 建议再找一个 A/B 级来源交叉 |
| **D** | 第三方转载、论坛、汇总类网站、AI 汇总报告 | 低 | ❌ 只能用来「发现」，不能用来自信地投 |

### 关键区分：转载 ≠ 核实

**同一个邮箱出现在五所高校的就业网上，它仍然是 B 级，不会变成 A 级。**

原因是：这五所学校可能都在转发同一份企业提供的简章。如果那份简章本身有错字，
五份转载会让错误更「可信」，而不是更正确。

真正提升可信度的是**来源类型的多样性**，不是数量：

```
企业官网      写了 hr@x.com   ← A 级，独立来源
高校 A 简章   写了 hr@x.com   ← B 级
高校 B 简章   写了 hr@x.com   ← 与 A 同源，不增加独立性

→ 真正的交叉验证需要「不同类型」的来源，比如：
   企业官网 + 官方招聘平台 + 企业公众号
```

## 二、找邮箱的正确顺序

```
1. 企业官网 →「人才招聘 / 校园招聘 / 加入我们」页面
2. 企业官方招聘平台（很多公司用 zhiye.com / 51job 微站 / Moka）
3. 高校就业网发布的原始简章（找 PageSource 而不是只看渲染结果）
4. 企业招聘公众号的历史推文
5. 官方就业服务平台公告
```

### 页面读不到正文怎么办

很多高校就业网是 JS 渲染的，抓取工具只能拿到页脚。

**处理原则：读不到就不算核实。** 可以尝试：

- 换一个浏览器/工具打开同一 URL
- 找同一条简章在别的学校就业网的版本（但注意上文的「转载不增加独立性」）
- 用页面的打印版 / 移动版 URL（常常是服务端渲染）

**如果都拿不到 → 暂缓，标注「未亲自核实」，不投。**

> 这不是过度谨慎。往一个错误的地址投简历，除了无效，还会让真正收到的人
> 看到一个连公司邮箱都没查对的候选人。

## 三、MX 体检

### 它检查什么

```
收件域名（如 example.com）
   │
   ├─ 有没有 MX 记录？          ← 没有 = 这个域名不收邮件
   │
   └─ MX 记录指向的主机
        └─ 这台主机能不能解析出 IPv4？   ← 不能 = 邮件送到一台不存在的机器
```

### 手动执行

```bash
# 1. 查 MX 记录
nslookup -type=mx example.com

# 期望输出类似：
#   example.com  MX preference = 5, mail exchanger = mx1.example.com
#   example.com  MX preference = 10, mail exchanger = mx2.example.com

# 2. 逐个查 MX 主机能否解析出 IP
nslookup mx1.example.com
nslookup mx2.example.com

# 期望输出包含：
#   Address:  203.0.113.10
```

### 三种结果怎么判

| 结果 | 含义 | 处理 |
|---|---|---|
| MX 记录存在 + 主机能解析出 IPv4 | ✅ 正常 | 可以投 |
| **MX 记录存在 + 主机解析不出任何 IP** | ❌ **致命** | **一定投不进去，换地址** |
| 完全没有 MX 记录 | ❌ 致命 | 换地址 |

### 为什么第二种最危险

因为它看起来是「配置好了的」——域名确实写了 MX 记录，写明了邮件该送到哪。
只是那台主机不存在。

**这种配置错误在企业域名里并不罕见**：换过邮件服务商、迁移过程中删了旧主机记录、
或者干脆是配置时打错了主机名。

而对发件方来说，这一切完全不可见：SMTP 服务器只负责把信交给对方，
它不会去验证对方 MX 主机是否还活着。

> 这就是本项目最重要的一条经验：
> **`SMTP 返回 250` 和「邮件送达」之间，隔着一整段你看不见的路。**

### 用脚本做

```bash
python scripts/preflight.py --dns
```

输出示例：

```
   MX  ：example.com → ✅ 正常（mx1.example.com, mx2.example.com）
   MX  ：dead-domain.com → ❌ 异常（MX 主机 orf.dead-domain.com 无法解析出 IPv4）
   阻断项：
     ✗ 收件域名 dead-domain.com 的 MX 不可用（MX 主机 ... 无法解析出 IPv4）——该地址一定收不到信
```

**MX 异常会自动变成阻断项，不会放行。**

### 实现上的两个坑

见 [`05-troubleshooting.md`](05-troubleshooting.md)：

- `nslookup` 在中文 Windows 下输出 GBK，用 `text=True` 会抛解码异常
- 用正则找 IPv4 时，如果 `nslookup` 先打印 IPv6，会误判成「没有 IP」

本项目改用 `socket.getaddrinfo` 判断主机是否有 IPv4，两个坑一起绕开。

## 四、RCPT 探测（可选，谨慎使用）

MX 体检只证明「域名能收信」，不证明「这个地址存在」。

RCPT 探测可以再进一步：连到对方 25 端口，走完握手，只问「这个收件人收不收」，
**不登录、不发正文**。

```
220 mx1.example.com ESMTP
EHLO preflight.local
250 OK
MAIL FROM:<>
250 OK
RCPT TO:<hr@example.com>
250 Recipient ok          ← 地址存在（或服务器不校验，一律接受）
```

### 判读

| 返回 | 含义 |
|---|---|
| `250` / `251` | 服务器愿意收——地址很可能存在 |
| `550` / `551` | 地址不存在 |
| `450` / `451` | 临时拒绝（可能是限流），无法判定 |
| 连接超时 | **无法判定**，不是「不存在」 |

### 必须知道的限制

1. **很多服务器不校验 RCPT**（catch-all），一律返回 250。这时 250 没有信息量。
2. **大量云主机与公司网络封了 25 端口出站**。连接超时是常态，不代表地址有问题。
3. **部分服务商会把频繁 RCPT 探测判定为攻击行为。** 不要批量跑。

**结论：RCPT 250 是加分项，RCPT 失败不是否决项。** 不要因为探测不通就放弃一个
来源可靠的地址。

```bash
python scripts/verify_delivery.py --probe
```

## 五、五个常见陷阱

### 陷阱 1：把「集团邮箱」当成「子公司邮箱」

大集团下每个子公司有独立域名。投 A 公司的岗位，简历发到 B 公司的邮箱，
大概率进不了流程。

**核对：公司全称里的法人主体，与邮箱域名是否对应。**

### 陷阱 2：把「咨询邮箱」当成「接收邮箱」

见 [`03-safety-rules.md`](03-safety-rules.md) 规则 3。

### 陷阱 3：忽略命名格式要求

很多简章要求「邮件主题与简历附件按『岗位+姓名+学校+专业』命名」。
不符合格式的邮件可能被规则自动归档，等于没投。

**核对：简章里有没有命名要求，附件文件名是否也符合。**

### 陷阱 4：抄送地址也失效

主收件人可用不代表抄送地址可用。
抄送地址失效会产生退信，退信多了会影响你的发件信誉。

**处理：抄送地址同样要做 MX 体检；查重时不要把同一地址同时放 TO 和 CC。**

### 陷阱 5：往个人邮箱投

`zhangsan@company.com` 这种一看就是个人邮箱的地址，常见于高校专场招聘的联系人。
它可能是有效的，但：

- 该员工离职/转岗后邮件就没人管了
- 它不是公司的正式投递入口

**处理：能用正式招聘邮箱就不用个人邮箱。用个人邮箱时，正文称呼要写「XX 老师」。**

## 六、核实记录怎么写

`VERIFIED` 字段要能回答三个问题：

```
① 在哪个页面看到的？（页面地址或页面名称）
② 那页上原话是什么？（逐字引用关键句）
③ 有没有交叉来源？（其他独立来源怎么说）
```

### 好的写法

```
企业官网「校园招聘」页原文「简历投递邮箱：hr@example.com」；
另在某大学就业网 2027 届公告同址，两处逐字一致。
```

### 不好的写法

```
❌ 多个高校就业网一致      ← 没说哪个页面、没引用原文
❌ 网上查到的              ← 不可追溯
❌ 应该是这个              ← 猜测
❌ 待核实                  ← 未完成，会被脚本拦下
```

**写不出「原话」，就说明还没核实完。**
