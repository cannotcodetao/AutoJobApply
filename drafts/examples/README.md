# 草稿示例

这三个文件演示三种不同场景的写法。**示例中的人名、公司、邮箱、学校全部是虚构的**，
邮箱域名统一用 `example.com` 系列，不会指向任何真实服务器。

| 文件 | 场景 | 要看的是什么 |
|---|---|---|
| `E1_标准技术岗.txt` | 常规技术岗投递 | 三段式结构的标准写法：每段对应岗位职责的一个具体侧面，而不是罗列技能 |
| `E2_诚实披露技能缺口.txt` | 岗位硬性要求里有一项你确实不会 | **如何把「不会」说得可信**：先讲匹配、再主动指出缺口、最后给出替代方案 |
| `E3_咨询邮箱场景.txt` | 简章上写的是「校招咨询邮箱」而非「简历接收邮箱」 | 正文必须明确「网申才是主渠道，此信作为补充」，不能让对方误以为这就是正式投递 |

---

## 怎么用

```bash
# 1. 复制一个最接近的示例
cp drafts/examples/E1_标准技术岗.txt drafts/D1_某某公司.txt

# 2. 改头部字段（五项必填：COMPANY / ROLE / LOCATION / TO / VERIFIED）
#    再重写正文——不要只改公司名，第三段必须针对这家公司重写

# 3. 出核对表
python scripts/preflight.py --dns --html

# 4. 用户确认后发送
python scripts/send_resume.py --send --approved --only D1
```

## 三个示例共有的写法

**每段都以「我做过什么」开头，而不是「我具备什么能力」。**

| 不要写 | 要写 |
|---|---|
| 我具备扎实的算法能力 | 我负责把改进后的检测模型部署到工控机运行，完成相机取流与联调 |
| 我有良好的团队协作精神 | （删掉。这句话没有信息量，且无法验证） |
| 我学习能力强，能快速上手 | 我在硕士期间独立完成从训练、部署、硬件联调到界面开发的全过程 |

**具体到能被追问，才算写了。**

如果一段话 HR 追问一句「具体怎么做的」你就答不上来，那这段话不如不写——
它只会把面试引向你最薄弱的地方。

## 一个反面提醒

`E2` 里的披露段落看起来像是「自曝其短」，实际效果相反：

- 它证明你知道这个岗位真正要求什么（很多候选人不知道）
- 它把「不匹配」这件事的解释权握在自己手里，而不是等面试官发现
- 它给出了替代方案，让对话可以继续

**包装出来的匹配度，会在面试第一个技术问题就崩。**
